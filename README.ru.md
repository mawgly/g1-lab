# SO-ARM101 — обучение виртуальной руки

Также добавлен эксперимент **Humanoid-v5 — обучение ходьбе**. Удобный просмотр и управление в браузере: **humanoid_browser.cmd**. Отдельное окно: `humanoid_watch.cmd`, обучение: `humanoid_train.cmd`. Подробности — [HUMANOID.md](HUMANOID.md).

Готовая модель SO-101 от The Robot Studio, физика MuJoCo и обучение PPO из Stable-Baselines3. Камера и собранный робот для этого проекта не требуются.

Проверенный результат от 15 октября 2026: **100 из 100 новых целей достигнуты**, среднее конечное отклонение **1,8 мм**. Случайное управление: **0 из 100**, среднее отклонение 26,66 см. Это результаты в описанной ниже рабочей области симуляции, не измерения на физической руке. Точные значения, контрольная сумма проверенной модели и результаты каждой попытки — в `runs/so101/evaluation.json`. Полный запуск обучения: 1 003 520 шагов (PPO округляет до полного пакета), около 4 минут на этом компьютере.

## Запуск двойным щелчком

- **demo.cmd** — обученная рука тянется к новым зелёным целям. Красная точка — точка захвата, которую она учится подводить к цели.
- **manual.cmd** — окно MuJoCo для изучения модели. В правой панели Control можно менять команды приводам, включая раскрытие захвата. Tab переключает панели; мышь вращает вид, колёсико приближает.
- **train.cmd** — новое обучение на 1 000 000 шагов. Лучше запускать после просмотра готового результата. Оно пишет в `runs/so101`; для сохранения прежнего результата используйте отдельную папку, как в примере ниже.
- **evaluate.cmd** — проверка на 100 новых целях и сравнение со случайным управлением.
- **setup.cmd** — повторная установка окружения и проверка тестов. На этом компьютере окружение уже подготовлено.

Окно симуляции закрывается крестиком. Во время обучения Ctrl+C сохраняет текущую модель в `last_model.zip`.

## Что именно учится делать рука

Пять суставов управляют положением руки, захват удерживается открытым. Нейросеть получает углы и скорости суставов, положение рабочей точки и цели. Она выдаёт небольшие изменения целевых углов сервоприводов. Физика рассчитывает движение с гравитацией, ограничением усилий и столкновениями.

Зелёные цели выбираются из достижимых положений настоящей модели, в ограниченной рабочей области перед основанием и выше пола. Успех: красная точка находится не дальше 2 см от цели пять последовательных тактов (0,2 секунды). На попытку даётся 6 секунд. Это обучение положению точки, без требования к ориентации захвата и без захватывания предметов.

## Команды PowerShell

Все команды выполняются из папки проекта:

```powershell
# Смотреть готовую модель
.\demo.cmd

# Новое обучение, сохранив предыдущую модель
.\.venv\Scripts\python.exe -m arm_sim.cli train --steps 1000000 --run-dir runs/experiment2

# Продолжить обучение
.\.venv\Scripts\python.exe -m arm_sim.cli train --resume runs/so101/last_model.zip --steps 500000 --run-dir runs/continued

# Проверить другую модель
.\.venv\Scripts\python.exe -m arm_sim.cli evaluate --model runs/experiment2/best_model.zip --episodes 100 --output runs/experiment2/evaluation.json

# Смотреть её
.\.venv\Scripts\python.exe -m arm_sim.cli view --model runs/experiment2/best_model.zip

# Проверки
.\.venv\Scripts\python.exe -m pytest -q
```

Обучение выполняется на CPU; 8 процессов считают независимые симуляции. Если компьютер нужен для другой работы, добавьте `--envs 2`. Окно MuJoCo использует графику компьютера. Интернет требуется при установке, обучение и просмотр работают локально. Платных API нет.

## Файлы результата

- `runs/so101/best_model.zip` — лучшая модель по промежуточной проверке.
- `runs/so101/last_model.zip` — состояние в конце обучения.
- `runs/so101/evaluation.json` — итоговые результаты по каждой цели и случайный контроль.
- `runs/so101/progress.csv` — ход обучения.
- `runs/so101/training_config.json` — параметры запуска и версия модели робота.
- `requirements-lock.txt` — установленные версии библиотек.

Python находится в `.tools/python`, библиотеки — в `.venv`. Ничего активировать и менять в системном PATH не требуется. При переносе проекта на другой компьютер следует заново создать окружение через setup.cmd; папки .tools и .venv не переносить.

## Источник модели

[TheRobotStudio/SO-ARM100, Simulation/SO101](https://github.com/TheRobotStudio/SO-ARM100/tree/main/Simulation/SO101), версия указана в `models/so101/UPSTREAM_REVISION.txt`. Несмотря на название репозитория, используется SO-101 follower. Исходные модели сохранены без изменений вместе с лицензией Apache-2.0. При загрузке программа добавляет пол, цель и метку рабочей точки, выбирает шаг интегрирования и настройки изображения.

Параметры симуляции приблизительны. Этот проект не отправляет команды в USB или моторы. Для реальной руки после сборки понадобится отдельная калибровка и проверка управления. Камера будет нужна для самостоятельного поиска предметов, а не для текущего эксперимента.

## Humanoid: три режима вычислений

В `humanoid_browser.cmd` можно выбрать CPU, GPU-физику с PPO на CPU или экспериментальный полный GPU. По умолчанию выбран режим GPU-физики. Полный GPU включается явно при создании нового эксперимента; до измерения скорости и проверки результатов его ускорение не считается подтверждённым.

- `setup.cmd` устанавливает основное CPU-окружение `.venv`.
- `setup_fullgpu.cmd` создаёт отдельное `.venv-fullgpu`: PyTorch **2.14.1+cu130** из официального индекса CUDA 13.0 и зависимости из `requirements-gpu.txt`. Установка проверяет доступность CUDA на NVIDIA GPU. Это окружение используют оба GPU-режима: в режиме GPU-физики PPO просто выполняется на CPU. Прежнее `.venv-gpu` больше не нужно и может быть удалено вручную.

В полном GPU-режиме физика MuJoCo Warp, действия нейросети, накопление опыта и обновления PPO выполняются на CUDA. Контрольные оценки и воспроизведение сохранений используют общую CPU-среду Humanoid-v5; поэтому во время оценок загрузка GPU может снижаться. Скорость физики отдельно не равна скорости всего обучения: сравнивайте переходы в секунду для полного цикла с одинаковым числом сред и одинаковыми настройками PPO.

GPU-физика использует Newton, исходная CPU-физика — PGS. Это разные вычислительные условия, даже при одинаковом Humanoid и награде. Перенос весов между ними оформляется отдельным экспериментом; совпадение траекторий не ожидается. Новые режимы и настройки сохраняются в отдельных папках лаборатории, а исходный эксперимент остаётся архивом. Полный GPU пока экспериментален: сначала выполните короткую проверку сохранения, CPU-оценки и скорости, затем выбирайте бюджет длительного обучения.
