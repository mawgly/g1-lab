# Humanoid-v5: смотреть, как робот учится

## Удобный просмотр в браузере

**humanoid_browser.cmd** открывает локальную страницу [http://127.0.0.1:8766](http://127.0.0.1:8766). Здесь есть 3D-модель с вращением мышью и приближением колёсиком, пауза, скорость 0,5× / 1× / 2×, выбор этапа ползунком и графики реальных результатов. Нажатие на точку графика тоже выбирает этап.

«Следить за новыми» включает переход к последним сохранениям между попытками. «С самого начала» показывает исходную модель. Обучение запускается и останавливается в лаборатории (см. ниже). Для сравнения этапов используются одинаковые пять начальных состояний.

Физика и нейросеть выполняются в Python, браузер отображает положения настоящих геометрических частей модели через WebGL. Это живая симуляция, не заранее записанное видео. Страница работает без внешних сайтов и интернета после установки. Сервер доступен только на этом компьютере. Если открыто несколько вкладок, они управляют одной общей симуляцией просмотра. Закрытие вкладки не останавливает обучение; для остановки нажмите соответствующую кнопку. При запуске через cmd не закрывайте консоль сервера, пока пользуетесь страницей.

Язык страницы выбирается справа в заголовке: русский (основной), английский или упрощённый китайский; браузер запоминает выбор. Переведены интерфейс, сообщения сервера, отчёт и дневник. Новые записи дневника, имена веток и заметки переводит `python -m humanoid_sim.journal_translate`: пока абзац не переведён, он показывается по-русски. Надписи внутри картинок, роликов и схем остаются русскими.

Если страница перестала открываться, снова запустите humanoid_browser.cmd. Если локальный сервер уже работает, этот файл просто откроет его страницу.

Сервер работает без окна: его чёрное окно больше не висит на панели задач, а окно humanoid_browser.cmd закрывается сразу. Журнал сервера — `runs\humanoid_lab\server.log`. Обучение, очередь и проверки тоже запускаются без окон. Если сервер не смог запуститься, появится окно с сообщением об ошибке. Выключать сервер не нужно, он почти не нагружает компьютер. Если всё же надо: Диспетчер задач → «Подробности» → python.exe, у которого в командной строке `humanoid_sim.webapp`.

## Три файла для запуска

- **humanoid_watch.cmd** — открыть окно с последним сохранённым этапом. Можно открыть и закрыть в любое время; обучение работает отдельным процессом.
- **humanoid_train.cmd** — запустить обучение или продолжить с последнего сохранения. По умолчанию ещё 2 миллиона шагов. Одновременно работает только один тренер для одной папки. Пока он работает, очередь и проверки лаборатории не запускаются, и наоборот.
- **humanoid_stop.cmd** — запросить остановку обучения с сохранением. Текущая проверка/сохранение может занять некоторое время; дождитесь статуса stopped в окне просмотра. Закрытие окна просмотра само по себе обучение не останавливает.

Все файлы запускаются двойным щелчком из папки проекта.

## Управление в окне

| Клавиша | Действие |
|---|---|
| ← / → | Предыдущий / следующий сохранённый этап |
| L | Вернуться к последнему этапу и автоматически подхватывать новые |
| Пробел | Пауза / продолжение просмотра |
| R | Начать новую попытку текущей модели |
| Esc | Закрыть просмотр |
| Мышь и колёсико | Повернуть вид и изменить приближение |

Слева сверху указаны **Watching stage** (сколько шагов прошла показываемая модель), **Mode** (LIVE latest или HISTORY) и **Training** (состояние тренера и общий прогресс). Числа Watching stage и Training обычно различаются: просмотр показывает законченное сохранение, а тренер уже учится дальше. Новая версия в режиме LIVE подхватывается между попытками, максимум после окончания 15-секундного эпизода. В паузе можно переключать этапы; для продолжения движения снова нажмите пробел.

Справа сверху — проверка на пяти фиксированных начальных состояниях: средняя награда, время до завершения попытки и продвижение вперёд в метрах. Максимальная длительность попытки — 15 секунд. Большая награда сама по себе ещё не означает красивую ходьбу: сравнивайте длительность, расстояние и сами движения.

## Какие этапы сохраняются

Этап **0** — исходная необученная нейросеть. Затем сохранения появляются по умолчанию каждый **1 млн шагов** (при создании эксперимента можно выбрать от 100 тыс. до 5 млн) на границе пакета обучения: интервал округляется вверх до границы пакета. Каждое сохранение проверяется на CPU несколько секунд, поэтому частые сохранения замедляют быстрое GPU-обучение. Ранние запуски сохранялись каждые 500 тыс. шагов. Последнее состояние сохраняется также при завершении или штатной остановке.

Папка `runs/humanoid/stage_XXXXXXXXXXXX` содержит нейросеть, соответствующую нормализацию наблюдений и результаты проверки. Это единый комплект: для воспроизведения нужны оба файла `policy.zip` и `normalize.pkl`. Этапы сохраняются отдельно и не перезаписываются.

На старте персонаж часто падает. Позже он может научиться дольше стоять, переминаться, прыгать или продвигаться вперёд. Улучшение не обязано быть плавным, поздний этап иногда хуже раннего. Это стандартная задача движения вперёд; естественная человеческая походка отдельно не задаётся. Два миллиона шагов — первый эксперимент, а не обещание освоенной ходьбы.

## Продолжение и отдельные эксперименты

В PowerShell из папки проекта:

```powershell
# Ещё 2 миллиона шагов с последнего этапа
.\.venv\Scripts\python.exe -m humanoid_sim.cli train --steps 2000000

# Список этапов и их результатов
.\.venv\Scripts\python.exe -m humanoid_sim.cli list

# Смотреть исходную модель
.\.venv\Scripts\python.exe -m humanoid_sim.cli watch --stage 0

# Новый независимый опыт, другая папка
.\.venv\Scripts\python.exe -m humanoid_sim.cli train --run-dir runs/humanoid2 --seed 7 --steps 2000000
.\.venv\Scripts\python.exe -m humanoid_sim.cli watch --run-dir runs/humanoid2
```

При высокой нагрузке можно использовать `--envs 4`. Обучение использует CPU и 8 независимых симуляций по умолчанию. Графическое окно запускается отдельно. Прогресс сохраняется в `runs/humanoid/status.json`, таблицы обучения — в подпапках `session_*`. В запущенном из Codex опыте консольный журнал находится в `runs/humanoid/training.log`.

Продолжение восстанавливает нейросеть, оптимизатор и статистики нормализации; случайные состояния физических сред начинают новые эпизоды. После аварийного выключения можно продолжить с последнего полного сохранения.

Среда: [Gymnasium Humanoid-v5](https://gymnasium.farama.org/environments/mujoco/humanoid/). PPO: Stable-Baselines3. Здесь нет камеры, физических моторов и платных API. Эксперимент с SO-ARM101 запускается своими прежними файлами.

## Лаборатория экспериментов

`humanoid_browser.cmd` открывает лабораторию на http://127.0.0.1:8766/.

- **Эксперименты**: исходный запуск защищён от изменения через браузер. Создайте новый запуск с нуля либо на основе лучшего/последнего сохранения. Каждая конфигурация сохраняется в собственном каталоге `runs/humanoid_lab/exp-...`.
- **Обучение**: добавьте выбранный эксперимент в очередь и запустите её. Серия создаёт три пресета PPO × seeds 42/43/44. Очередь выполняется отдельным процессом и продолжает работу после закрытия вкладки или сервера. Остановка сохраняет текущую модель и оставляет следующие задания ожидающими. После аварийного завершения автоматического перезапуска нет.
- **Смотреть** (и кнопка «Смотреть» в истории) — **забег этапов**: от 1 до 10 сохранённых этапов на соседних дорожках одной сцены. По умолчанию первый, средний и «Последний · следить» — эта дорожка между забегами переходит на новое сохранение, поэтому ею же следят за идущим обучением. «Дорожек» распределяет выбранное число этапов равномерно, «Лучший и последний» задаёт эти два. Все стартуют одновременно с одной стартовой позицией и одной командой (стоять, 0,5 / 1,0 / 1,4 м/с, стоп-старт); каждая политика работает в своей физике, дорожки сдвинуты только на экране. Пауза, «Заново», скорость и «На весь экран» общие. В таблице — скорость за 2 с, смещение вперёд и вбок, шаги в минуту (как в «Проверить походку»), момент падения и «За что награда»: средняя награда за шаг цветной полосой (вправо от черты — поощрения, влево — штрафы, цвета подписаны над таблицей); «Подробно по составляющим» показывает числа. После окончания забег повторяется со следующей из пяти стартовых позиций. Забег не прокручивается: если окно слишком низкое, прокручивается страница лаборатории. Рука SO-101 не ходит, для неё остаётся простой проигрыватель.
- **Настройки задачи G1** при создании эксперимента: «Держать курс» — нулевая команда поворота превращается в возврат на исходное направление (иначе робот постепенно разворачивается); «Штраф за наклон корпуса» — корпус над талией с наклоном около 6° вперёд при ходьбе и вертикально стоя. В сохранениях, созданных до этих настроек, их нет, и их поведение не меняется.
- **Сравнение**: графики до четырёх экспериментов на одной шкале абсолютных шагов и таблица настроек. Исходные оценки — пять фиксированных seeds, повторная диагностика — 30 других seeds. Награды после изменения задачи нельзя сравнивать без дополнительных условий.
- **Отчёт**: параметры, история сессий, графики, компоненты награды новой проверки, разброс результатов и источники. Отчёт первого запуска: `runs/humanoid/report.html`. Обновление отчёта не меняет исходные модели.

### GPU

Оба GPU-режима используют одно окружение `.venv-fullgpu`, которое устанавливается через `setup_fullgpu.cmd`. В режиме «GPU-физика» NVIDIA GPU выполняет MuJoCo Warp физику, а PPO/PyTorch выполняется на CPU. Это не полное обучение на GPU. Браузер показывает реальную общую скорость обучения отдельно от теста физики. Настройки по умолчанию: 256 сред × 32 шага = 8192 перехода на обновление, мини-пакет256. Не увеличивайте одновременно число сред и длину пакета без учёта памяти.

GPU использует **Newton** (PGS исходного XML не поддерживается), float32 и RK4. Отдельные контактные силы отличаются от CPU float64; тесты проверяют движения, награды, падения, сбросы и перенос сохранения на CPU. Все итоговые оценки и просмотр выполняются на исходном CPU Humanoid-v5/PGS. В отчётах это обозначается как проверка переноса между вариантами физики.

Тест скорости запускается из браузера, когда очередь остановлена. Полный замер сохранён в `runs/humanoid_lab/gpu_benchmark.json`; включает обмен наблюдениями/действиями и сброс попыток, исключает обновление PPO. Холодная компиляция CUDA может занимать около минуты. Никаких облачных сервисов или внешней публикации не используется.

Новый ночной таймер задаётся в форме эксперимента. Запуск прекращается при достижении **первого** лимита: числа шагов или времени. Для восьми часов обучения увеличьте бюджет шагов до достаточного значения. Сон блокируется только при включённом таймере; экран может гаснуть. Изменение настроек требует нового эксперимента.

## Проигрыватель и ночной режим

Ночной режим включается полем часов при создании эксперимента. На время запуска Windows получает временный запрет автоматического сна; экран может погаснуть. После таймера или остановки модель сохраняется, процесс завершается и запрет сна снимается. Финальное сохранение и оценка могут занять дополнительное время. Настройки электропитания не изменяются, компьютер не выключается. Перезагрузка Windows и пропадание питания не блокируются. Вкладку можно закрывать.

«Проиграть этапы» показывает сохранения с первого до последнего. Настройте секунды на этап (реальное время, пауза останавливает отсчёт) или одну попытку до указанного лимита. По умолчанию при завершении попытки остаётся прежнее замирание на 0,6 секунды. Для просмотра физического падения включите «Полное падение + 2 с» перед запуском этапов: после неудачи моторы расслабляются, показывается приземление и ещё 2 секунды (страховочный предел продолжения — 8 секунд симуляции). Успешная попытка, закончившаяся по лимиту среды, не превращается в искусственное падение. Этот показ не меняет обучение и оценки. На последнем этапе просмотр останавливается; выбор этапа вручную отключает последовательный режим.
